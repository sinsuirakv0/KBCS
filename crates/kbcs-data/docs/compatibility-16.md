# JP 16.0.0と未実装データ

公式データと計算コアの版を分ける。統合原本 `integrated-jp-1600000-4-1` の `versionCode` は1600000。計算コアの参照版は15.7.2、ABI 5。変換器15で再取り込みし、既存のSQLite schema 8、編成JSON、C++の構造体を共用する。

## 取り込みと状態

- 既知のCSV・JSON構造は引き続き検査する。未知IDを持つ有効なレコードは `unsupported` として原本を保持する。破損・型違い・既知構造の必須列不足はエラーを返す。
- `talents::import` は未知本能に補間を行わず、最大Lvと元の行・枠位置を保存する。`talents::read` が `source_file` の14列を復元する。`maintenance::summary` は本能IDごとに件数とキャラ数を集約する。
- 味方119列、敵113列までの既知の数値形式を維持する。追加された有効値は列番号・値とともに表示し、旧コアへは既知部分だけを渡す。図鑑の追加行は原本配列を別に返す。未実装の本能玉はIDとパラメータを保持し、装着候補や画像部品の入力から外す。未知のコンボ条件・効果や特殊ルールには状態と原本を残す。
- `Data/Roguelike*` は採用原本の索引から取得できる。既存の通常ステージと分け、Roguelikeの進行・抽選・報酬計算は未実装として診断に集約する。

## 本能73とコンボ392

参照はJP 16.0.0 ARM64、SO SHA-256 `1a79a59c382c2edcfc7ed76c97bfd8488ac24f87aa6958009e8dea46f2d85bd3`。リモートの `b14e74e937` にある関数ページと比較窓 `fa9cbdc8303e1b3a86470d44` を使用した。

`0086151c` は `SkillAcquisition.csv` の14列を各枠へ読み込む。`005c8ebc` のID `0x49` の分岐は先頭パラメータをコンボの索引として説明へ差し込む。`008c3294` は取得状態が正の本能73の先頭パラメータを使い、種別7のコンボを状態2から1へ変える。`00a47d08` / `008c28e8` はロック状態を保持し、`008c41ac` はその状態と先頭5枠のキャラ・形態で発動を判定する。`00b1dc60` はコンボ原本、`00b1b3c0` は図鑑原本の読込入口。

原本のキャラ358・本能73は最大Lv0、先頭値392。KBCSの編成は取得済みフラグを0/1で保持し、数値補間やC++の本能配列を通さない。コンボ392「骨まで愛して」は、解放と先頭5枠・形態がそろった場合に適用する。本家のアカウント全体の本能取得状態は、KBCSでは編成内に保存した取得状態で表現する。図鑑行88は能力ID −1・本能ID73であり、戦闘個体の能力フラグではない。従来の88要素の戦闘情報ウィンドウABIはそのまま使う。

## 計算の精度

施設とお宝は採用元SHAを確認する。`param.tsv` と施設の項目名・対応表は、ファイルが異なる場合にも、実際に参照するキーと行が一致するか検証する。`param.tsv` の既存の数値キーは16.0.0でも一致した。未確認の入力値の変更は従来どおり計算を拒否する。

戦闘開始・フレームの `runtime.precision` は `status` と重複を除いた `issues` を返す。参照版との差、出撃メンバーの有効な未知本能・装備・追加列、出現し得る敵の追加列、該当編成の未実装コンボ、選択マップの未実装ルールを追跡する。`partial` は参照版と全計算が一致する保証がない。教師データや回帰の入口では `require_exact: true` または `battle-replay --require-exact` で部分計算を拒否できる。低水準の数値APIは渡された値だけを評価する。

戦闘UIは参照版で生成した画像と切り出し座標を組で使用する。16.0.0で画像または切り出し定義が変わった場合は、その旨を戦闘の情報欄に表示する。音声の定義は従来どおり原本のハッシュを照合する。

## 確認範囲

Windowsで16.0.0の統合原本を隔離DBへ取り込み、888キャラ・2,635形態を生成した。15.7.4も統合原本から882キャラ・2,618形態を新規取り込みし、生成済みの旧DBと新規DBの両方でキャラ358とステージの取得を確認した。16.0.0ではキャラ358の本能73と図鑑行88を確認し、戦闘APIで未取得、取得済みの先頭5枠、取得済みの2段目を比較した。隔離DBに本能901と能力列119を加え、詳細画面の警告、既知本能の操作、戦闘APIの精度情報を検証した。Chromiumで出撃準備から戦闘を開始し、参照版素材と精度の注意を表示したまま論理フレームが進むことも確認した。

Windowsの `cargo test --workspace` は65件、UIのNode.jsテストは7ファイルが通過した。

16.0.0の本家判定は保存済みの擬似コードと原本データで照合した。16.0.0の実命令による戦闘全体の比較は未実施。Roguelike、未知効果、アカウント全体のコンボ解放状態は上記の範囲に留めている。
