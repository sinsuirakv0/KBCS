# 外部評価の再確認と修正（0.1.10）

対象はJP15.7.2 ARM64 / ruleset1507021、SO SHAは[native照合](native-calculation.md)と同じ。2026-10-22。評価の各項目を保存原本と実命令で再確認した。完全な戦闘ランタイムの実装とは区別する。

## 出現と乱数

`random.cpp::kbcs_core_random_bounded`を追加し、Rustの`random::Random`が明示シードの状態を所有する。uint32のxorshift（左13、右17、左15）の更新後に正のboundで剰余を取る。bound=1でも更新する。原本のseed=0時のOS初期化を再現可能なカーネルへ持ち込まず、seed=0とbound<=0はエラー1、出力も状態も変更しない。新しい型/関数をABI2へ追加し、既存PODを変更しない。

`research/verify/rng.py`は0044a8d8/0044a8e8を実行し、4種の初期状態×8回=32段階の戻り値と状態を比較する。009f1e64は個体枠探索から最初の能力getterまでを5条件で局所実行。空き1番/50番、逆転したレイヤー範囲、空きなし、不正な敵IDを確認した。空きなしと敵ID−1ではこの区間のレイヤー抽選はなく、範囲1の生成でも1回進む。能力getter以降の全個体初期化と、その内部の追加乱数を検証したという意味ではない。

006ef2b0では生成戻り値だけを制御した2条件も実行。失敗時は間隔抽選なし・seen未変更、成功時は全体bound5→行bound1の順で2回更新され、game+0xda58の初回出現フラグが1となることを確認した。この試験の生成stubにはレイヤー抽選を含めていない。将来の所有ランタイムは次の関係を保持する。

1. tickで候補を取得。
2. 個体枠を探索し、原本が要求する地点で同じ乱数状態からレイヤーを抽選。
3. 生成成功後に全体間隔、続けて行間隔を抽選しcommit。
4. 原本と同じ地点でenemyId別のseenを更新。原本では全体間隔・行間隔・生成回数を更新した後に記録する。

現在のcommitは個体生成やseen配列を所有しない。失敗時に禁止するのは**成功後の間隔乱数**であり、生成内部で既に消費した乱数を巻き戻さない。完全な生成処理と全乱数列の統合は今後の作業。

## commitの検証と所有権

生C ABIは有限生成数の使い切り、撃破条件、城条件も検査し、不正なら状態を変更しない。Rustの`stage::tick`は行/状態/Contextを借用した`PendingSpawn`を返す。`.index()`と`.row()`で候補を参照し、生成成功時だけ`.commit(self, ...)`で消費する。生成失敗時は破棄する。従来の公開index指定commitは非公開にした。借用中の別tick・状態差替えと同じ候補の2回commitを型で防ぎ、2回commitのcompile_failテストも通した。

C ABI単独は状態所有者を持たず、0待機・無制限行の再commitを識別できない。将来C++から直接使う場合も同じ消費型候補を所有ランタイムで包むこと。Rustの改善を生C ABIの完全なトークン検証と混同しない。

## 命中計算

超獣・超賢者・怪人の有効ビットが立っているのに対応rate=0ならエラー1。無効ビットの0は許可する。城経路ではこれらを適用しないので0も許可する。怪人の有効/無効は原本のコンボ判定を呼出側で解決し、0コンボなのに有効ビットを立てない。ゼロを標準倍率で暗黙補完しない。

`kbcs_core_prepare_attack`→Rust `prepare_attack(AttackPreparation)`を追加。原本両命中関数のparam_6=0/1/2を別入口で処理する。attack×percentを、kind2では500、それ以外では100で整数除算。kind1はその結果へwave_percent/100を適用。wave_percentは原本battle_wave_s_st取得値に相当する。kindは原本の数値区分として保持し、波動/烈波/爆波というUI名をまだ割り当てない。C++の通常HitInput.attackは準備済み値という契約。HTTP/UIへ新入口を追加したわけではない。

`calculation.py`は両原本を18準備条件で実行し、kind別・割り切れない数値を比較する。乗算が原本のi32範囲を超える入力は拒否する。全状態getterや攻撃発生/伝播は未実装。

直接命中48条件について、ネイティブの実PCで保持レジスタを採取し**21段階すべて**を比較する。最終値から逆算した中間値ではない。城対象は元関数の城個体番号getterも整えてクリティカル/渾身の4組合せを確認した。超ダメージ/打たれ強いコンボの整数化、魔女/使徒コンボ0・99・100、本能玉との複合を含む。毒撃4条件と割合予約は別経路のまま。

対象外攻撃・呪いは呼出側がblocked/有効能力を解決する契約。原本の対象選択から命中入口までの全状態を用意した検証は残る。バリア・シールド・回避・生存・蘇生・波動等の生成と時計もこの計算だけでは再現できない。
