# 計算コアとFFI（ABI 4）

C++20の純粋な整数計算を、Rustホストと将来の戦闘ランタイムで共用する。GUI・SQLite・描画・ファイル・OSの乱数源へ依存しない。明示状態の乱数カーネルは別入口とする。敵と味方の公開入口を分け、共用するのは段階ごとの整数演算と明示した共通順序だけ。純粋計算に加え、現在は`kbcs_battle.h`のBattle handleが戦闘状態を所有する。[所有ランタイム](battle-runtime.md)と[0.1.35の現状](../../../docs/plans/review-v0.1.35.md)を参照。以下の版付き追記や初期カーネルの未実装記述は当時の範囲であり、現在の所有戦闘と区別する。

[戦闘エフェクトの状態監査（2026-10-30）](effects-audit-20261030.md): 呪いの素材誤登録、バリア/盾の表示時計、死亡時の描画経路を修正。実命令による根拠と未検証の範囲を記録した。

## 呼出関係

- `kbcs_core_stat`：基礎値と成長率→お宝→コンボ→通常本能→超本能。`StatOutput.stages`は成長・お宝・コンボ・本能・超本能・最終値。攻撃は各段を別々に呼び、後で合計する。
- `kbcs_core_unit_hit`：味方→敵の直接攻撃。`calculateHit(..., false)`へ渡す。
- `kbcs_core_enemy_hit`：敵→味方の直接攻撃。`calculateHit(..., true)`へ渡す。
- `kbcs_core_unit_metal_killer`：味方側の現在HP割合攻撃を1件処理。Rustの`unit_metal_killer`が同じFの予約順に繰り返し、割合計算用の基準HPを減らす。通常攻撃の保留値とは分ける。
- `kbcs_core_enemy_poison`：敵側の毒撃。味方の最大HP→割合・最低1→毒撃耐性・最低1→毒撃用装飾。通常攻撃・メタル・土台・属性特性の経路を呼ばない。
- `minimumPercentage`：割合と最低1の整数演算だけを共用する内部関数。
- `kbcs_core_expectation`：整数化済みの非発動／クリティカル／渾身／両発動の4結果を確率で加重する。乱数の生成・抽選順は扱わない。
- `kbcs_core_stage_tick / stage_commit`：借用した状態へ出現待機・候補選択・成功後の間隔更新を行う。[ステージ設計と範囲](stages.md)。敵個体の生成と戦闘全体は別。

`kbcs-bridge`の安全なラッパー→C ABI→上記関数。`Service::handle`のPOST `/api/calculate`は`stats / unitDamage / enemyDamage / metalKiller / poison`を別の配列として受ける。未知の項目は拒否する。純粋計算APIのPOD入出力は呼出中だけ借用し、保持しない。所有Battle/Areas/Hits/背景演出は入力を複製し、ヒープを使う。例外はC ABI内で捕捉し、エラーへ変換する。作成/破棄・借用期間は各APIの契約に従う。

## 入力の単位と責務

|項目|単位・意味|
|---|---|
|stat.growth|Lv1=100の累積成長率。原本の10Lv区間からホストが組み立てる|
|stat.treasure|章別の最大加算×完成率を各章で整数化した合計。完成率300%そのものではない|
|hit.attack|成長・お宝・コンボ・本能適用済みの一撃|
|hit.raw_attack|味方のLv1原本一撃。本能玉の加算だけに使う|
|critical / strengthen / weaken / savage|攻撃側の発動状態・確定効果量。味方側と敵側で入力元を入れ替える|
|abilities|味方→敵では攻撃側の特効、敵→味方では防御側の特性。対象一致・呪い・特殊種別を解決したビット集合|
|fruit|一致した対象属性に対応する果実の最大完成率合計（0〜300）。複合属性でも同じ特性を二重適用しない|
|strong_orb|与ダメージ時は1/1000の加算値、被ダメージ時は軽減%（ネイティブの玉集計関数の出力と同じ）|
|massive_orb|超ダメージの分子への加算値（分母300）|
|attack_orb|原本一撃へ加算する%。S相当500なら原本の5倍を加算|
|defense_orb / resistant_orb|ネイティブが集計した軽減%。装着・解放条件の判定は別領域|
|behemoth_rate / sage_rate / villain_rate|1/1000単位。原本param.tsvやコンボから渡す。コード内の既定値を採用しない|
|base_reduction / decoration_reduction|原本の1/10000単位。対象属性・攻撃種別・Lvを判定して渡す|

味方には撃破後強化玉の段があり、敵の攻撃側には適用しない。通常の属性特性、魔女、使徒、超生命体、超獣、超賢者、怪人の順で評価する。土台等を通った後に非クリティカルのメタル1化を行う。毒撃とメタルキラーは別入口。

0は成功、1は入力範囲、2は整数上限エラー。演算にはi64を使い、主要な段で非負i32の範囲を確認する。ネイティブの32bit乗算が桁あふれする割合入力も拒否する。桁あふれ時のゲーム挙動を再現したという意味ではない。

## 検証と未実装

根拠は[ネイティブ照合](native-calculation.md)、特性の区分は[特性監査](ability-audit.md)。現在の54種のキャラ特性をすべて区分した。状態処理をダメージ倍率に置換しない。本能玉の装着UI・解放条件、波動等の発生・伝播、バリア・シールド・回避・生存・蘇生、妨害の時計、撃破報酬、味方の生産回数の管理は未実装。

ABIの互換性とゲームの演算仕様の版を分離し、ruleset_versionは1507021を返す。ホスト応答のrulesetとUI定義のversionCode、DBのgameVersionを照合し、未確認の別版へ現在の計算を黙って適用しない。

0.1.7では0番台のXPを`kbcs_core_legend_experience`へ追加した。出現とXPの契約・局所実行の範囲は[ステージ](stages.md)。

0.1.8で出現待機のinitializeと開発素材のplan/pickを追加。完全な戦闘開始や報酬所持数の更新は含めない。[契約と照合](stages.md)。

0.1.9は敵のステージ倍率→冠→クリスタル不足加算を`kbcs_core_enemy_stat`、0番台通常報酬の候補選択/取得済み分岐を`kbcs_core_legend_reward_pick`へ追加。型と所有権・検証範囲は[ステージ](stages.md)。敵城の攻撃は冠を除外する。既存Web表示への全接続・報酬実付与とは区別する。

0.1.10は[外部評価の確認・修正](audit-20261022.md)。候補の単回消費、明示状態の乱数、攻撃種別の準備、21段階の照合とエラー出力の原子性を追加した。

0.1.11は1000番台の通常報酬・重み選択とイベントXPを共通化した。[入口・関数関係と検証範囲](event-rewards.md)。既存の0番台用入口は維持する。

0.1.12は[スコアと重み報酬の確定](stage-score.md)。スコア旗のある309面の要求と、mode−3/−4の履歴/付与要求を共通C++へ追加。実所持数の付与と所有ランタイムは未実装。

## 0.1.13の追補

[所持数・保存先・時計・EX抽選](inventory-ex.md)。スコア旗309面のうち保存番号なし8面は原本が処理を省き、有効301面へ訂正。通常取得済みもヘッダー専用保存番号を使う。旧版の照合件数を実対象の完成数と混同しない。実所持数の数値245定義とEX抽選を追加し、専用通貨・解放・永続化・期間判定は別途確認する。

0.1.14の[39000番台までの共通入口・実測・未確認範囲](../../../research/docs/stages/all-bands.md)。stage_source、stage::Row::decode、experience::stageを追加。原本の分類とファイル選択を、専用戦闘ランタイムの完成と混同しない。

0.1.16のmotion.cppは通常KB24F→共通/専用魂の最大長→退場の閲覧用時計を返す。elapsed/返却frameはF、phase=0/1/2。xはモデルpx（DB距離15/2.5ずつ）、yはジャンプ差分のnative/10。描画のzoom/facingは含めない。根拠は既存15.7.1 ARM32の限定KB/死亡検証を参照し、現版全戦闘一致とは区別する。姿勢・補間自体は既存JS評価器のままで、C++移植は残る。

0.1.21の[描画コア](render.md)は浮動小数を含む姿勢と描画命令、独立した演出状態を追加する。上記の「ヒープ割当なし・状態を保持しない」は従来の数値カーネルを指す。描画コアの例外はC ABI内で捕捉し、エラー3を返す。GPU処理は引き続きホスト側。

戦闘画面の暗転・経済・ページ/入力の初期コアは[battle-screen.md](battle-screen.md)。個体の生成・攻撃状態を実装済みとは扱わない。

通常生産と敵生成の呼出入口は[production](production.md)。生成後の資金/待機確定、出現RNG/seen、初期座標、再生産値/時計を追加した。個体能力の構築と画面への接続は別に残る。

個体生成・属性/捕捉・抽選・妨害・時計・被弾予約と保護/生存/KBの状態カーネルは[actors](actors.md)。全形態の生成値と局所状態は現版ARM64へ照合した。上記の未実装一覧のうち純粋な状態関数を追加しているが、画面と全戦闘への接続は未完了。

烈波/反射待ち/爆波は[二次攻撃の所有状態](secondary.md)へ追加。生成後の周期/区画履歴、命中呼出、反射、寿命と退場待ちを扱う。命中内部の全条件や戦闘全体の一致とは区別する。

命中本体とC++所有戦闘の通常出撃への接続を[battle-runtime](battle-runtime.md)へ追加。従来の未接続の記述は各時点の記録であり、全戦闘・全ステージの完全一致は引き続き未完了。
