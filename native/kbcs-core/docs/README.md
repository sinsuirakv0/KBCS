# 計算コアとFFI（ABI 2）

C++20の純粋な整数計算を、Rustホストと将来の戦闘ランタイムで共用する。GUI・SQLite・描画・ファイル・乱数へ依存しない。敵と味方の公開入口を分け、共用するのは段階ごとの整数演算と明示した共通順序だけ。戦闘全体の状態更新を実装したものではない。

## 呼出関係

- `kbcs_core_stat`：基礎値と成長率→お宝→コンボ→通常本能→超本能。`StatOutput.stages`は成長・お宝・コンボ・本能・超本能・最終値。攻撃は各段を別々に呼び、後で合計する。
- `kbcs_core_unit_hit`：味方→敵の直接攻撃。`calculateHit(..., false)`へ渡す。
- `kbcs_core_enemy_hit`：敵→味方の直接攻撃。`calculateHit(..., true)`へ渡す。
- `kbcs_core_unit_metal_killer`：味方側の現在HP割合攻撃を1件処理。Rustの`unit_metal_killer`が同じFの予約順に繰り返し、割合計算用の基準HPを減らす。通常攻撃の保留値とは分ける。
- `kbcs_core_enemy_poison`：敵側の毒撃。味方の最大HP→割合・最低1→毒撃耐性・最低1→毒撃用装飾。通常攻撃・メタル・土台・属性特性の経路を呼ばない。
- `minimumPercentage`：割合と最低1の整数演算だけを共用する内部関数。
- `kbcs_core_expectation`：整数化済みの非発動／クリティカル／渾身／両発動の4結果を確率で加重する。乱数の生成・抽選順は扱わない。
- `kbcs_core_stage_tick / stage_commit`：借用した状態へ出現待機・候補選択・成功後の間隔更新を行う。[ステージ設計と範囲](stages.md)。敵個体の生成と戦闘全体は別。

`kbcs-bridge`の安全なラッパー→C ABI→上記関数。`Service::handle`のPOST `/api/calculate`は`stats / unitDamage / enemyDamage / metalKiller / poison`を別の配列として受ける。未知の項目は拒否する。POD入力と出力のポインタは呼出中の借用のみで、C++は保持しない。コアはヒープ割当と例外を使用しない。

## 入力の単位と責務

|項目|単位・意味|
|---|---|
|stat.growth|Lv1=100の累積成長率。原本の10Lv区間からホストが組み立てる|
|stat.treasure|章別の最大加算×完成率を各章で整数化した合計。完成率300%そのものではない|
|hit.attack|成長・お宝・コンボ・本能適用済みの一撃|
|hit.raw_attack|味方のLv1原本一撃。本能玉の加算だけに使う|
|critical / strengthen / weaken / savage|攻撃側の発動状態・確定効果量。味方側と敵側で入力元を入れ替える|
|abilities|味方→敵では攻撃側の特効、敵→味方では防御側の特性。対象一致・呪い・特殊種別を解決したビット集合|
|fruit|一致した対象属性に対応する果実の最大完成率合計（0〜300）。複合属性でも同じ特性を二重適用しない|
|strong_orb|与ダメージ時は1/1000の加算値、被ダメージ時は軽減%（ネイティブの玉集計関数の出力と同じ）|
|massive_orb|超ダメージの分子への加算値（分母300）|
|attack_orb|原本一撃へ加算する%。S相当500なら原本の5倍を加算|
|defense_orb / resistant_orb|ネイティブが集計した軽減%。装着・解放条件の判定は別領域|
|behemoth_rate / sage_rate / villain_rate|1/1000単位。原本param.tsvやコンボから渡す。コード内の既定値を採用しない|
|base_reduction / decoration_reduction|原本の1/10000単位。対象属性・攻撃種別・Lvを判定して渡す|

味方には撃破後強化玉の段があり、敵の攻撃側には適用しない。通常の属性特性、魔女、使徒、超生命体、超獣、超賢者、怪人の順で評価する。土台等を通った後に非クリティカルのメタル1化を行う。毒撃とメタルキラーは別入口。

0は成功、1は入力範囲、2は整数上限エラー。演算にはi64を使い、主要な段で非負i32の範囲を確認する。ネイティブの32bit乗算が桁あふれする割合入力も拒否する。桁あふれ時のゲーム挙動を再現したという意味ではない。

## 検証と未実装

根拠は[ネイティブ照合](native-calculation.md)、特性の区分は[特性監査](ability-audit.md)。現在の54種のキャラ特性をすべて区分した。状態処理をダメージ倍率に置換しない。本能玉の装着UI・解放条件、波動等の発生・伝播、バリア・シールド・回避・生存・蘇生、妨害の時計、撃破報酬、味方の生産回数の管理は未実装。

ABIの互換性とゲームの演算仕様の版を分離し、ruleset_versionは1507021を返す。ホスト応答のrulesetとUI定義のversionCode、DBのgameVersionを照合し、未確認の別版へ現在の計算を黙って適用しない。

0.1.7では0番台のXPを`kbcs_core_legend_experience`へ追加した。出現とXPの契約・局所実行の範囲は[ステージ](stages.md)。

0.1.8で出現待機のinitializeと開発素材のplan/pickを追加。完全な戦闘開始や報酬所持数の更新は含めない。[契約と照合](stages.md)。
