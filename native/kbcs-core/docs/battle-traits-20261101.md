# 戦闘特性・出現・操作の修正監査（2026-11-01）

## 原本と確定した差分

BattleConfigへred_gauge_framesを追加したためABIを5へ上げる。ホスト・bridge・コア・UIを同時に更新する。ゲームのruleset=1507021、公式DBのスキーマは変更しない。

参照: JP15.7.2 / arm64-v8a / SO SHA256 `6122e24879d58db6b0beceb43e2a6ee62d008a586fc03b7cb7726214bc86f3ea`。保存済み疑似コードと同一SOの実命令を使用。別版のGhidraプロジェクトは使用していない。

キーキュー撤去はユーザー指定のPC操作変更。本家にキーボードがあるという意味ではない。描画RPCが処理中でも入力RPCを送信するが、独立した戦闘状態や待機リストは作らない。0tickでは論理F・表示F・経済を進めない。通常の5表示tickの押下待ちは維持し、即生産チートでは同Fに生成する。受理されなかったキーは保存しない。2段のSpaceは無効。応答の表示F/論理Fを確認し、古い応答でUIを戻さない。

終了カメラはmovingだけでなく、1段10000 / 2段8803までの自動ズームも完了条件に含める。完了前の原本演出を操作で中断せず、完了後も固定し続けない。

## フレーム印とゾンビキラー

00a9dce8はunit-modeでは107を書き換えない。この分岐を省略して両陣営の107を直接0にしない。常設ゾンビキラー能力を読む00a9a1ecは **108**、通常敵に受けた命中印を読む00a9dc78は **107**。添付評価の簡略な説明と区別する。

131/191は00a9bd84/00a9cf6cを通す。114（死亡結果）、130（バリア耐久）、184/190（盾最大/現在耐久）、133/192（表示状態）を解除対象に含めない。拡張枠もActorPoolScopeの同じ走査へ含め、命中ごとの解除にはしない。

エンジェル砲/ゾンキラ攻撃＋通常攻撃の同F致死、砲の翌Fの通常致死、ゾンキラ攻撃から3F後の通常致死、ゾンキラ攻撃後の生存を連続検証した。同Fだけ114が立ち、生存中は立たない。

## 特殊敵城・遅延の詳細

「億万長者オークション / 大富豪の暇つぶし」は15.7.2のData/stageRA081_00.csv。castle_raw=787 / DB敵ID=785。該当行がcount=0（無限）・再出現2Fのままで、初期の城生成後も通常出現していた。原本00a06db4の実命令と定数テーブル0x2b1c00を確認し、同じ補正を一致する全行へ適用した。CSV・DBの原本は変更せず、特定ID例外も作っていない。

HealthResult.delay_framesは既存ABI名を維持するが、内容は **遅延率%**。正値のword248と現在待機>0を条件に回収し、006db348で同陣営全体のhealth/react後、出撃枠別に32bit合算した率を適用する。赤印がない、または現在待機が保存最大値より小さい場合だけ遅延前の待機を保存する。`progress = recharge - wait`に率を掛け、原本の32bit積・符号付き除算・0下限を保って進捗を戻す。待機setterのflag=0を保持し、保存最大値を増えた待機で上書きしない。

赤印はbattle_red_gauge_frame。原本Data/param.tsvに項目がない場合、原本呼出しの既定値15を使う。別経路の減算/解除は未確認なので、推測の15Fタイマーを追加していない。005d18a4は黒97×14、内部93×10、赤幅 `(recharge-maximum)*93/recharge`、水色幅 `(recharge-wait)*93/recharge`。赤印と生産回数は別状態。

## 敵の城破壊4倍

元データ26列 → Definition::from_raw → 009f1e64 → 個体59 → 味方城slot0 → 006e79bc → 予約19 → health後HPを検証。15.7.2の敵35「こぶへい」の実rawで26列だけOFF/ONにした所有戦闘では **2637 / 10548** の城HP減少。生成後の59も0/1だった。既存4倍は有効で、式へ倍率を重複追加していない。
