## 通常比較と候補数

本家はmodeが負なら候補数1。それ以外は2番目の比較値が負なら1、3番目が負なら2、それ以外は3。共通CSVは1番目の比較値が5列、2番目が9列、3番目が12列（0基準）。負値を0に補完して候補を増やさない。stage_pickの負modeでcount!=1は入力不正として拒否する。

各候補でbound100の乱数を消費し、roll<chanceを先頭から評価する。レーダーも比較乱数を消費するが比較値を100として扱う。mode1/2の先頭当選では取得済み状態を調べ、未取得なら記録要求を返す。取得済みなら通常時は次候補、レーダー時は候補なし/打切りとなる。後続候補の取得済み判定へ拡張しない。

## 重み選択

mode−3/−4は5列と9列以降の3列組から比較値を合計し、その合計をboundとして**1回**乱数を取得する。先頭から累積重みがrollより大きくなる枠を選ぶ。重み0の位置を詰めず、合計が1でも乱数を消費する。レーダーで重み抽選を通常の確率比較に置き換えない。

C++は終端を確認した1..10枠の非負重みを受理し、合計は正のi32。weight_total→同じランタイム所有の乱数状態でbounded(total)→weight_pickの順で使う。空・全0・負重み・範囲外rollをエラー1、合計超過を2として出力を変更しない。原本では11枠すべて埋まると候補数を0へ戻すが、合計をboundにした乱数は1回消費して候補なしとなる。この異常経路を境界11条件で記録し、製品APIでは11枠を拒否する。

戻すのは正規化した候補番号であり、実付与ではない。mode−3はその後に00a09734の履歴と記録処理を持つ。mode−4は別の付与/結果行生成経路へ進む。重みの選択結果だけで未取得フラグやレーダー返却を確定しない。

mode−2の原本には通常先頭候補の後にも追加セル群がある。0.1.11時点のカーネルは通常の先頭比較までで、追加報酬を実付与したり、無視して完成扱いしたりしない。
