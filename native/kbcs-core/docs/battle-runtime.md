## 所有と呼び出し

`battle-screen.js` → `POST /api/battle-session` → Rust `battle::Session` → bridge `Battle` → `kbcs_battle.h` / `actor_battle.inc`。C++が102個体、生成通番、出現行/待機、再生産、RNG、命中予約/寄与者、波動/区間/履歴、烈波/反射/爆波を所有する。Rustは原本と編成の解決、Mutexによる排他、描画素材と転送を担当する。

作成後は `/api/battle-session/frame` にsession、Input、カメラ条件だけを送る。JSのコピーで戦闘状態を上書きしない。KBF1/KBG1と既存WebGL面を共用し、返却stateの残高、wait/maximum、城HP/個体数を表示する。終了/pagehideはDELETEで所有状態を解放する。旧stateless HUD/DBプレビューAPIは維持する。session最大8、同一session内は直列、他session/DB閲覧は別ワーカー。

HUDの各論理更新内で敵出現/個体時計/行動/攻撃/命中を進め、5表示tickの入力ガードが解けた時点で出撃を確定する。HTTP batch末尾のrequest_slotだけを後処理しない。`advance`で失敗した所有者は以後進めない。frame/phase/side/slotの診断を返し、部分更新を成功として継続しない。

主要順序は006d6d04の出現 → clock → 味方006eb464/敵006eccf4 → intent → attack_wait/同Fのattack → 波動の進行/命中 → 烈波/反射待ち/爆波 → メタルキラー予約/全個体のprotect → 敵城個体の値を城0へ同期 → 被弾表示RNG/health/死亡集計/react。ゾンビキラー表示30枠の寿命は各論理Fで進める。陣営0の死亡数が出現条件へ渡る経路を、敵の撃破数と取り違えない。敵城の原本49列が有効な場合だけ、00a951e0（word112）の累積被ダメージを出現条件へ使う。撃破玉243は選ばれた枠だけを敵走査後に解除する。

命中本体と局所照合は[hit-runtime](hit-runtime.md)、波動/二次攻撃の所有は[secondary](secondary.md)、生成と再生産は[production](production.md)を参照。

チートは本家の仕様として解釈せず、kbcs_core_battle_cheats(handle,flags)で明示する。1=所持金無限、2=同時/総生産数と50体上限の解除、4=再生産/キャラ押下後の待機なし、8=精霊召喚ボタン非表示。未知bitは状態を書き換えず拒否。元の設定・出撃禁止理由・式は保持し、全OFFの既存経路を継続する。固定の編成禁止理由は数量上限と区別する。

資金は財布上限を表示し、費用が上限より高いキャラも生成時だけ必要額を保証して、後で財布表示へ戻す。再生産は待機/最大を0へ、battle_screen_advance_customの即時フラグはキャラ解放だけを直接deployへつなぐ。アイテム/オプション等の5表示更新待機は維持。通常のscreen_advance/stepは即時フラグ0で同じ本体を呼ぶ。非表示中の精霊枠は通常生産へ戻し、解除時に既存の召喚状態を再表示する。

通常のactors[2][51]・Clock・選択PODのABI4形状は変えない。actor_pool.incが所有Battleの51番以降をdequeへ確保する。参照の安定性を保ち、既存個体の退場後には空き番号を再利用する。TLS ActorPoolScopeは同じhandleの同期呼出だけで借用し、別戦闘/スレッド/単体APIへ漏らさない。敵の生成枠は本家の50体のまま。解除後も出現済みの追加個体を削除せず、通常上限を超えている間は追加の通常生産を許可しない。

生成だけを増やす方式ではなく、時計、意図、接触、単体/範囲攻撃、妨害、保護、被弾、吹き飛び、死亡/勝敗、コンボ寄与、波動/烈波/爆波履歴まで同じ個体参照へつなぐ。範囲攻撃の対象が51件を超えたときは同期の拡張対象列を貸し、能力/RNG抽選を対象51件ずつ再実行しない。元の51件PODを外部へはみ出して書かない。

原本のアドレスを保持するresearch資料には触れず、生成器のactor_pool_source.pyが個体仮想アドレス/陣営stride/走査終端だけを共用表現へ変換する。相対offset c810/c83c/c840も含む。通常の上限は51、算術/分岐/RNG順は同じ。追加領域は仮想strideと整数表現/実メモリの範囲で有界（50体固定制限とは独立）。

kbcs_core_battle_actor_refsは本体をコピーせずactiveな個体のポインタ/陣営/番号/profileを返す。Rustが同じ所有者を排他で借用し、描画とstatsは追加個体も含む。描画は従来の敵→味方収集とレイヤー選択ソート。被弾描画バッファの必要量も追加枠に合わせる。旧actors読取は通常51枠だけを返す互換入口。

検証は既存の原本照合fixtureを含むworkspace33＋compile_fail1と、battle-cheats.cppの合成4条件。80体の通常攻撃・範囲被弾・波動・烈波・爆波を同じ所有ループで進め、1番/80番の同じHP、即生産/資金/ステージ数量上限、OFF復帰、精霊ボタン切替を検査する。合成チート試験は本家に存在しない条件であり、原本ARMと同一という意味ではない。実画面と大量個体のGPU性能はユーザー確認/別の計測範囲。
