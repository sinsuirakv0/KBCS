### 生成と通常生産

SpawnRequestは009f1e64のparam_2..8。side=0味方/1敵、raw=DB ID+2、level_index=内部0始まり（基礎値getterへは+1）、form=0..3、row=敵の読込行番号。通常味方のrowは0。Lv上書き/解放条件/形態は原本の取得経路で解決して渡す。

stage_widthと返却X/Yは原本内部整数座標。DB距離から×4で、描画pxへ直結しない。探索は1..50の前から最初で、occupied[0]は使わない。死亡/魂でも原本の枠が使用中なら非0を渡す。通常Xは味方width−2800、敵2800、敵城に一致する枠は3200、Y=4480。raw=−1はslot=−2、満員は−1。この2経路はレイヤーRNGなし。

レイヤーはmin+RNG(max(0,max−min)+1)。逆転でもbound1を1回消費する。敵の逆転した行間隔の「非正boundなら0/状態不変」と混同しない。ボス最終XはcastleX−trunc(scale×1180/100)+trunc(scale×offset/10)+trunc(scale×127/10)。寸法率0も保持する。

deployのallowed/present/blockedは005bc910/005bcdec/009e583c相当の解決済み判定。costは005be130相当の1/100円、rechargeは0058c05c相当の論理F。制限・動的状態・資金・待機を実行時に揃える。生産回で変わる費用を固定値として永続キャッシュしない。

構築コールバックは009f1e64相当の実体を呼び、成功1..50/失敗−1/無効原ID−2を返す。prepareの枠番号をそのまま成功として返してよいのは局所試験だけ。実使用ではHP/能力/初期行動/占有登録まで完了させる。callback中は回数加算前なので偶数/奇数生産の玉等は現在数+1のプロフィールを選ぶ。

成功後だけlast_cost、produced、total、資金、wait/maximumを更新する。成功SE19。失敗SE15は条件不成立では常に要求し、構築失敗だけ原本param_4相当のnotify_failureで抑止できる（SE−1=要求なし）。通常生産に任意の財布点滅を加えない。

reduction=−1は短縮条件なし、0..100は条件成立後の短縮率。短縮時はmax(trunc((100−R)×base/100),min(base,60))。recharge_enabled=0は待機設定省略。精霊召喚モードは費用/回数の扱いが異なるためエラー4で拒否し、通常生産へ代用しない。精霊持ちキャラの通常生産後の15F準備も実構築側に残る。

rechargeのbase/talentは読込後F。研究力Lvは0058b674(7)相当の内部値、treasureは効果11の集計値、comboは0088f9e4の効果11、stage_percentは特殊ルール6の対象レアリティ率。A=max(base−talent,0)、B=6×Lv+treasure、C=max(60,A−B−trunc(B×combo/100))、最後にtrunc(C×stage_percent/100)。固定ルール1はoverride_framesをそのまま返す。固定0と指定なし−1を区別し、率適用後に60へ戻さない。

clockは1論理Fに1回。waitが現在baseを超えたFはwait/maximumをbaseへ戻し、そのFには1を減らさない。それ以外は正のwaitを1減らす。0へ達した枠だけreadyビット（SE27要求）を返し、0のままの枠は毎F通知しない。

### 敵・開始処理

enemy_tick内で候補を消費し、別commitを呼出側へ公開しない。有限数・城条件を最終候補へ再適用せず、既存の連続tick仕様を保つ。active_enemiesは使用中の1..50枠数（特殊敵城を含む）。構築失敗では成功後の2抽選/seen更新を省く。構築内部で消費済みのRNGは戻さない。seenの添字はraw−2、既存の非0値は上書きしない。

startは空の出現表でも開始間隔を1回抽選。敵城rawの最初の一致行だけwait=1/spawned=1。通常の「成功後commit」を敵城初期化へ転用しない。敵城指定/モード/HP/倍率/特殊条件の解決はstage_source/データ側の契約と合わせる。

## 所有権と画面への接続

バッファ/callbackは同期呼出中だけ借用しポインタを保持しない。同じ戦闘用の非0シードを構築と間隔抽選へ順番に渡す。背景演出の独立RNGを代用しない。0のOS初期化は持ち込まない。

0/1/2は成功/入力・構築契約不正/整数境界、4は未対応召喚。エラーと正常な満員を区別する。callback前は入力を検証するが、実構築開始後のエラーは全体のロールバックを保証しない。callbackが行/Contextを変更したり、規定外の戻り値を返した場合は戦闘を停止する。RustのpanicはFFI内で捕捉し、C++復帰後に再送出する。

006d6d04の論理更新（敵出現/再生産/収入）と入力更新（解放後5回待って味方生成）は別。現行battle_screen::frameは複数tickをまとめるため、最後のrequest_slotだけを後から処理すると生成時刻がずれる。接続時は各論理更新/入力更新の内部へ置く。JSに別の生産計算/待ち時計を追加しない。今回は最適化済み戦闘API/ワイヤ形式を変更していない。
