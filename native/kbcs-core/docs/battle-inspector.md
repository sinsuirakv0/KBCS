# 所有戦闘の個体観測（2026-11-04）

一覧・型・状態フィールド・画像の準備とUI接続は[戦闘個体一覧](../../../ui/docs/battle-inspector.md)を参照。

`actor_inspector.inc` の `BattleInspector` は本家の個体配列と分離したKBCS用の補助記録。`construct` の成功、health/react後のHP0、行動14→15、raw0による退場を観測する。観測処理は251語やseedへ書き込まない。枠→記録の索引は追加個体プールにも対応し、生成のたびに新しいidを付ける。全生成記録を保持するが、計算時に走査するのは個体枠だけで、過去の記録を毎F走査しない。C ABIは読取専用の借用配列を返し、既存PODの配置・ABI5は変更しない。

最小の所有ランタイム回帰試験で、同じ枠の再利用前後で別記録になること、蘇生動作への遷移を1回だけ数えること、退場後も最終値を保持すること、複数回の読取りでRNGが変わらないことを確認した。app10件・bridge36件・doc1件、UIの7検査、app/bridge all-targets release clippyを通過。画面操作・見た目の確認は利用者が担当する。


2026-11-05: word19の予約を原因スコープで観測し、HP0確定Fの攻撃元を保存する。二次攻撃とメタルキラーの遅延適用でも生成元idを維持する。左右一覧・複数攻撃元・保護処理との関係は上のUI設計文書を参照。
