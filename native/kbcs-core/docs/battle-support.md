## 自城体力

`009eadc8 → 0058b7d4` が初期体力を作り、`00a92f3c → 00a95864` が最大体力へ保存し、`00a92f50 → 00a958f0` が現在体力へコピーする。

0058b7d4は施設6の内部Lvを0058b674で取得する。内部値Lは表示Lv合計から1を引いた値。基礎値はL<4なら1000+1000L、4<=L<8なら2000L-2000、8以上なら3000L-9000。

`0063a620` は `Data/CC_Castle_growth.csv` を読み、`0063c560` は表示Lv1から区間補間する。現版の行は(10,0,36000,0)、(20,36000,76000,0)、(30,76000,116000,0)。全区間とも1Lvあたり4000で、開発Lv1の加算は0、Lv30は116000。レシピ0の名称は `res/CastleRecipeDescriptions.csv` の「にゃんこ城強化」。

原本の最終値は `(基礎値 + 開発加算 + 00a5b084の効果0) * (100 + 0088f9e4のコンボ効果10) / 100`。効果0は日本編group4（北陸の豪邸）と未来編group2（古代の石版）。00a5b084は10章分のベクトルから同じeffectTypeを集めるため、日本編だけに限定しない。6章それぞれ最大7000を章別に整数化して合算する。施設Lv20+10の78000＋開発Lv30の116000＋お宝42000＝236000、コンボなしの通常最大。0.1.26の215000は未来編3章分の入力漏れだった。スニャイパーは11800。

`kbcs_core_castle_health` は解決済みの施設Lv合計1〜30、開発Lv1〜30、お宝加算0〜42000、コンボ%を受ける。元の施設上書き・固定モードの選択は呼出側の責務であり、全ステージの上書きをこの関数が解決する意味ではない。正常時だけ出力を書き込む。

## スニャイパー

- アイテムの内部番号は5。`005ce564` が更新、`005cefb4` が描画、`006eccf4 → 005ced48` が弾の到達判定と命中処理。
- `005ce564` は有効な敵個体1〜50を調べ、指定の城個体を除き、最大X座標を候補にする。同位置では後の個体へ更新する。照準角の追従、個体状態、射出時の再確認もあるため、単純な10秒周期の即時命中へ置き換えない。
- 待機値は300Fで飽和。準備動作11F目に、照準が一致し対象が有効なら弾を生成する。待機は準備開始時と弾生成時に0へ戻る。弾の飛行時間は別にある。
- `00a9327c → 00a95824(side,0)` は最大自城体力を20で整数除算する。現在体力ではない。メタルは1ダメージ。成功時にノックバック要求フラグを立てる。
- 攻撃無効の残り時間が正なら、その弾はダメージ判定の乱数を引かない。無効中でなければ、確率0でも必ず乱数100を取得する。乱数が攻撃無効確率未満なら発動し、ダメージを予約しない。
- 成功経路はその後に命中演出の乱数100,60,100,60も取得する。局所関数での直接消費は成功時5回、攻撃無効発動時1回、既に無効中0回。headlessでも描画都合で省略しない。
- OFFの更新経路は既存の弾・演出の有効フラグを消去する。将来のON/OFF実装で時計だけを止めない。

`kbcs_core_sniper_hit` は到達済み・有効対象に限定した数値カーネル。対象選択・除外、弾移動、射撃時計、乱数取得、状態更新、4回の演出乱数の適用はランタイムへ残る。出力random_consumedは上記の直接呼出し回数を返し、関数自身がRNGを進める意味ではない。通常の味方攻撃や敵毒撃と入口を共有しない。

## スピードアップ

原本 `Data/param.tsv` の `boost_speed=3`、`res/GatyaitemName.csv` の0番もOFF・2倍・3倍を説明する。`006d6d04` はアイテム0と3倍選択フラグを調べて1/2/3を設定し、同じ戦闘更新を指定回数ループする。敵出現・スニャイパー等もそのループ内。F数やダメージを倍率で書き換えない。

`research/verify/battle_support.py` は同版ELFのSHA・ABIを検証し、ARM64をUnicornで実行する。0063c560の7境界、0058b7d4の8条件、005ced48の6条件、00a5b084の日本/未来/両方/部分設定4条件を確認した。009e505cの20条件、00aa0568の7条件も同じ実SOで比較する。外部状態取得・効果予約等は管理したスタブであり、全フレームの戦闘再現ではない。

## 出撃制限とコスト（0.1.27）

009e4474はStage_option.csvの冠-1・面-1を展開して辞書へ書き込み、後の行が同じキーを上書きする。UIは表示行を全部ANDにせず、元の順で最後に一致した行を選ぶ。009e505cの選択済み行の判定をkbcs_core_deploymentへ移す。非0のレア度bit、準備時の1ページ目制限、コストの上下限と逆転区間、Charagroupの0/1/2、SpecialRulesMapのレア度別編成枠を別の理由bitで返す。group1は準備時に許可し戦闘側で限定する元の分岐を保持する。UIは準備と出撃の両結果を保持する。maxUnitsは動的な同時出撃上限であり、編成メンバー数として判定しない。
