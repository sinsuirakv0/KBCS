# 本能玉の集計と戦闘への反映

基準はJP 15.7.2 / 1507021 / Android ARM64、SO SHA-256 `6122e24879d58db6b0beceb43e2a6ee62d008a586fc03b7cb7726214bc86f3ea`。原本 `equipmentlist.json` の310件を順番どおりID 30000–30309として読む。属性ビットは `equipment_attribute.csv` から読み、赤・浮・黒・メタル・天使・エイリアン・ゾンビ・古代・白・魔女・使徒・悪魔の順に扱う。

`equipment::Catalog` → `Session::new` → `battle::equipment` → `kbcs_core_battle_equipment`。出撃前に適用可能な玉をスロット順に解決する。C++の`Definition`には合成済みベクトルと種類別の存在、`Profile`には属性一致の集計に必要な個々の値を残す。`hitContext`は相手の属性と最大2個の玉を照合する。戦闘中に原本データを読み直さない。既存のPODの配置とABI 5を維持する。

## 照合の範囲

- `research/verify/equipment.py` は同SHAの実命令で原本310件、110組の複数装着・複合属性・空欄、同等級の異なる効果値2順、枠解放境界8件を照合する。`tests/equipment-vectors.json` は原本データのSHAと結果を保持し、ARM64環境がなくてもRustテストで利用できる。原本コンテナの配置と一部の外部取得関数は検証ハーネスで制御する。
- `0065f258` は88件を照合した。素の能力・属性の取得は実命令、対象属性を追加する本能の取得と第4形態の所持状態は制御入力。現在の形態で有効、別形態で有効、非対応、玉17・19の排他を比較した。
- `actors.py` の個体生成284件、`actor_hit.py` の命中1,263件、`battle_special.py` の生産回数48件・再生産短縮16件・価格1,944件に同じ版の原本値を使う。`actor_generated.inc` の妨害、死亡時効果、被弾後遷移への接続は既存の原本由来の分岐を維持した。全戦闘の発生フレーム、描画・SE、全特性の複合発動までの連続照合は未実施。
- `0078aefc` / `0078af80` に、元マップ48・ステージ3とアカウント進行を参照する追加の適用経路がある。KBCSの任意ステージ出撃にはその進行コンテキストがなく、この2経路は未接続。
