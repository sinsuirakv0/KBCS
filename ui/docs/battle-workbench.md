# 戦闘の操作盤・詳細・表示上限

上部の操作盤と下部の詳細を分離する。初期タブは「動作・PC」で、スマホ接続中の戦闘では端末側の計測を隣の「スマホ」タブに表示する。敵/味方一覧から個体を選ぶと個体詳細を開く。ステージは城/個体/制限/スコアと出撃時に固定した情報、動作・PCは `/api/runtime` を使用する。KBCSのRAMはホスト分のみ。

個体の生成IDを `focusActor` としてフレーム要求に添付する。選択タブが見えている時だけ要求する。Rustは既存の観測記録から生成IDを解決し、退場していなければ描画ループで個体の本体・登場・魂に対応する命令範囲を記録する。同じ応答の座標を拡大・中央配置してプレビューへ渡す。別時計で先行再生しない。退場した個体は数値を保持し、再利用された枠を描かない。JSONメタデータのみ追加し、KBFレコードとC++ ABIは変更しない。

ログは最大80行で、表示フレーム間のHP・行動・妨害・バリアなどの確定値の差分を記録する。バッチを挟む場合は論理Fの範囲を表示し、その途中の変化や変化の直接原因を断定しない。次の候補は、ダメージ確定と妨害適用を個体ID付きイベントにし、予約量・防いだ量・HPに反映された量を分けること。生の内部値や抽選は開発者向けの別表示を想定する。

描画上限は既定・最大30 FPS。設定は10～30 FPSから選ぶ。`battlePresentationClock`は描画開始の予定時刻を`1000 / 上限`ms刻みで進め、タイマーの小さな遅れを次の間隔へ積み重ねない。予定から大きく遅れたときは実際の開始時刻から刻み直す。`scheduleUpdate`は次の論理Fが貯まる時刻にも処理を起こす。一度に持ち越すtick数の上限と1F/10F操作、C++内の計算は維持する。平均FPSは実測値を表示する。

戦闘中はキャプチャ段階でキー割り当てを解決する。マウスで操作盤・一覧などを操作した後は盤面へフォーカスを戻す。文字入力やモーダルダイアログは引き続き各UIがキーを受け取る。大画面表示は出撃準備のチェックボックスまたは戦闘操作盤から有効にする。KBCSの表示領域を盤面に使い、画面比率を自動に切り替える。Escで元の比率と操作盤へ戻る。

操作盤の「全画面表示」で、デスクトップ版は戦闘用のモニターと、必要に応じて操作盤用の別モニターを選択できる。`desktop.rs` がOSの全画面と別WebViewを管理し、`battle-display.js` が既存の操作盤・敵味方一覧・詳細を同一オリジンの別ウィンドウへ移す。同じDOMと戦闘セッションを使用するため、操作・一覧の選択・詳細ログを引き継ぐ。Esc、別ウィンドウの「通常表示に戻る」、別ウィンドウを閉じる操作で元の配置に戻る。ブラウザー版ではFullscreen APIを通じて現在のモニターで全画面表示できる。

撃破元は元の個体ポートレートと分け、数値欄の下に30×22pxのアイコンを置く。戦闘計算の精度はRustの `precision.issues` から日本語の判定理由を表示する。戦闘UI素材の版差は独立した項目として表示し、開くと原本パスと欠測・内容差を確認できる。

パーツ省略はアルファ判定の負荷が上回ったため廃止した。通常の描画順と頂点をそのままWebGLへ送る。

描画完了時に、実時間上すでに経過したtickがあれば次の要求を直ちに送る。戦闘フレーム要求は1件ずつで、カメラ入力とFPS上限の扱いはそのまま。非表示のステージ情報は更新を休止し、開いた時に最新値を取得する。初回の個体用テクスチャ転送は最大32 MiBまで暗転中に行う。測定は「動作・PC」でWebGL提出、HUD提出、受信後の描画待ちに分ける。WebGL提出時間はGPU実行時間ではない。
