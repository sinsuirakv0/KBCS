# 既存ステージの出撃準備（0.1.28）

ステージPlayの「既存マップから」→既存stage-searchのplay=1モード→stage-sortie。通常のDB検索・詳細画面は維持する。playフラグはnative-stateがURLに保持し、検索条件は従来の検索UIを流用する。普通の検索へ戻るとplayを除去する。

## UIと保存

左は選択マップ内のステージ一覧。中央はステージ名・冠・折りたたんだ敵一覧・使用編成・自城体力・6アイテム・出撃。右サイドバーは詳細なステージ情報・有効な出撃制限・特殊条件・固定編成・背景と城・BGM試聴。長い報酬表・出現条件表はDB詳細に残す。抽選ステージは原本候補を明示選択するまで出撃を無効にする。

GET /api/formations?list=1はID・revision・名前だけを返す。選択した1件のprofileを取得し、編集はそのIDの編成画面を開く。battleFormationは設定をコピーしてresolveFormationMemberを通し、Lv不足の第四形態や超本能を実効値へ変換する。出撃前に保存revisionを再確認し、変更されていれば再確認を求める。出撃操作で編成DB・公式DB・本家の所持品を変更しない。

城砲にはdevelopmentLevel（城開発Lv1〜30）を追加。編成単位で保存し、古いファイルの欠測は30として扱う。施設の「お城体力Lv20+10」とは別。castleHealthInputは施設合計・日本編group4と未来編group2の章別お宝・先頭5枠の城体力コンボを組み、POST /api/battle-support→Rust bridge→C++へ渡す。画面の値は編成の設定値による見積もりであり、特殊ステージの施設上書き処理はまだ接続していない。

アイテム0〜5はスピードアップ・レーダー・ネコボン・ニャンピュータ・おかめ・スニャイパー。速度は2/3の選択で、OFF時のsnapshotは1。選択はsessionStorageだけへ保存する。城体力・スニャイパー・速度の原本と範囲は[native設計](../../native/kbcs-core/docs/battle-support.md)。

## 2026-10-28: 操作盤のチート・再生速度・平均FPS

チートボタンで4設定を開閉する。初期値は全OFF、各戦闘で独立し、自動で有効にしない。明示したflagsを各frame要求でC++所有Battleへ渡す。ブラウザ側で所持金や再生産状態を捏造せず、runtimeの金額/待機/可否を描く。精霊ボタン非表示はC++のHUDと生産入口の両方を切替え、その間は親キャラを通常生産できる。すでに出現した精霊や召喚内部状態を削除しない。

速度はアイテムに従う/通常1倍基準の1..20倍。battlePlaybackRateは表示更新の要求頻度を本家のspeed_mode+1で割り、3倍アイテムと20倍設定を掛けて60倍にはしない。暗転/原本の一時停止/終了時には追加倍率を適用せず、1F/10Fは従来のcontrol10で指定した論理Fだけ進める。最大30表示更新のbatchと原本の更新順を保ち、達成できない負荷でもFを捨てない。指定倍率は目標で、性能による待ちは既存のバーへ表示する。

平均FPSはbattle-screenのactivePaints×1000/activeMs。戦闘開始からの描画回数と実時間を累積し、非表示/ホスト停止/原本停止/暗転中を除く。計算F数やGPU実行数ではない。battle-monitorは瞬間FPSの隣へ表示し、診断にも同じ値とチート/速度を含める。画面確認はユーザー担当。

## 2026-10-29: 停止中の即生産と低速再生

ホスト操作盤の停止中、再生産時間無し（flags=4）が有効なときだけCanvasのreleaseを0tickで送る。C++の同じHUD当たり判定で枠を特定し、hook1→所有Battle::deployを呼ぶ。frame/ui_frame/hud_frame・経済・敵の出現時計は進めない。出撃による支払いや個体生成/RNGは実行する。通常の停止時の出撃不可と、本家オプションメニューの遮蔽は変えない。

速度の選択へ0.1/0.2/0.25/0.5/0.75倍を追加。battlePlaybackRateは0.1..20を通常1倍基準で扱い、本家スピードアップとの二重掛けを避ける。小数の蓄積から整数tickだけを送る既存の時計を使う。論理Fを間引かず、1F/10F操作は指定F数を保つ。


## 2026-10-29: 出撃準備での編成並べ替え

キャラ枠のクリックは同じ画面で選択し、長押しの並べ替えは編集と同じformation-reorder.jsを使う。詳細なLv/本能等の編集へは明示した「編集」リンクを使う。上の「キャラ枠から編成編集へ」という初期接続の説明を更新する。準備画面からの枠外ドロップでは削除しない。

変更した正式10枠は同じ/api/formationsへid/revision/documentを送って保存する。保存と城体力/出撃制限の再計算が終わるまで出撃・編成切替・追加のドラッグを止める。先頭5枠の入替えはコンボに影響するため、既存castleHealthとstageDeploymentへ必ず戻す。計算や施設・本能の入力式をUIに複製しない。競合・応答断では保存済み版を再取得し、未保存の並びを出撃へ混ぜない。明示リンク以外のキャラ枠から編集へ遷移する処理は削除した。

## 2026-10-30: 入力保持と結果通知の取得

キーボード入力は1個の変数へ上書きせず、64操作までFIFOで保持する。0tick/押下ガード/段切替中は消費せず、更新可能になってから既存C++のreleaseへ送る。1段の枠番号は送信時のページで解決し、Space直後のキーも次のページへ対応する。通常の5表示tick待機は省略しない。停止中の0tick消費は再生産無しチートの出撃だけ。停止操作/非表示/戦闘終了で古い入力を残さない。

勝利文字の開始は005e1a5cのphase0で20表示更新＋終了カメラの完了待ち。005e97d8はphase1から描画する。実DBの既存fixtureでも勝利750→文字開始770、空通知の終了操作可能831を確認した。原本の待機値を短縮せず、報酬通知の準備だけphase0から開始する。5倍率の配置を通知ごとに並列要求せず50件までまとめ、Serviceの64件/16KiB以内で順に取得する。ウィンドウの開閉時計はC++のまま。再現は隔離DB/保存先で実行し、実画面はユーザー確認。

キー用control拡張は、直前のgesture/holding/hold_framesを新しいタップの初期状態へ戻す。Space/スワイプ後のgesture=1が後続キーまで遮蔽していた差を修正した。通常のpointer releaseは従来どおりgestureを見て拒否する。
