# 戦闘個体一覧（2026-11-04）

KBCS独自の観測UI。本家UIの再現部分とは分離する。左に敵、右に味方の縦一覧を置き、それぞれ場内／退場／すべて・ページ・選択個体の詳細を独立させる。1ページ64体、各区分は生成順、39pxの2行表示。「すべて」は場内を先、退場を後にする。詳細な因果ログと全体イベントのタイムラインは次の段階。

## 所有・呼出関係

`KbcsBattle::construct` → `BattleInspector::spawn` が生成成功を記録し、KBCS用idを発行する。idはセッション内で一意。原本のword240（serial）、陣営、枠番号も別に保持する。枠が再利用されても過去のレコードと選択を上書きしない。

`logical` のhealth／react後にHPが正→0となった回数、`action` の14→15で蘇生動作へ移った回数を観測する。死亡数はhealth/reactでのHP0の延べ回数で、退場数ではない。勝敗確定後の一括退場を撃破へ加算しない。`sample` は変更の終わった個体を読むだけで、raw0を検出したら退場Fを一度だけ記録する。場内数はrawを保持し、昇天4／死亡時烈波21ではない個体数。骨・潜行・ワープも含む。生産数は既存の通常生産total、生成数には精霊・追加生産・砲の生成物も含む。

`kbcs_core_battle_inspection` → `Battle::inspection` は所有コア内の小さいPOD記録を借用する。次の変更操作まで有効。読み取りでRNGや戦闘状態を更新しない。記録はセッション終了時に破棄し、保存DBへは書かない。

Rust `battle_inspector::page` が陣営・範囲・ページと全体集計を作り、`/api/battle-session/frame` の任意のinspection要求へ返す。JavaScript `createBattleInspector` は通常は最大5Hz（ステップ・入力直後は即時）、両パネルが非表示なら要求しない。要求は既存フレーム通信へ同梱する。タブ変更・選択はrevisionで古い応答を棄却し、一時停止中も0tickで再取得する。画面の行数は64体まで。全履歴はC++で生成数に比例する小さい記録だけを保持し、毎F全履歴をJSON化しない。

## 開始前の画像準備

`Session::inspection_assets` が読み込み済みのC++ ModelからKB0F・待機0F・魂0Fと、共通zombie_downの最終静止姿勢のPacketを作る。本家の表示用に独自のアニメーションを追加しない。この0Fの選択と64×48の余白・縮尺は一覧用の設計で、本家UIの座標を意味しない。

開始時の暗転中に、既存のNativeWebGLRendererで部品順・ブレンドを描き、64×48 Canvasへ保存する。KB画像の白黒化もここで一度だけ行う。同一のPacketとtextureの画像、白黒画像は準備内で共有する。通常アイコンが欠けた場合は同じモデルの待機姿勢を使う。状態アイコンも先にdecodeする。開始後は完成画像の参照選択だけで、モーション計算・白黒変換・GPU画像生成を行わない。キャッシュはセッション内に限り、別版のアセットを流用しない。

生存時はキャラアイコン、蘇生待ちは骨、死亡・退場は白黒KB＋魂を表示する。被撃破側の小アイコンは重ねない。HP0になったフレームの有効な攻撃元を複数表示し、キャラは攻撃元の画像、砲・スニャイパー・その他は専用の文字印にする。5件以上は行画像では先頭3件＋残数、個体詳細では全件を表示する。貢献者集合から撃破者を推測しない。

## 最小検証

bridgeの所有ランタイム試験で、生成・14→15・退場・同じ枠への再生成と、読み取りによるRNG不変を確認する。Rustでページ・集計・ページ外の選択保持、JSで骨／退場の優先順位・耐久0・蘇生0・潜行∞を確認する。実際の画面確認は利用者が担当する。

2026-11-05: 表示範囲の切替で再追加した過去の行が末尾へ並ぶ不具合を修正。`orderActorRows`で応答の生成順に戻す。正しい順の行は挿入し直さず、通常更新での不要なDOM移動を避ける。範囲切替後の順序と、同じ順序の再適用で移動0回になることを回帰検査する。


## 2026-11-05 攻撃元の接続

`InspectorScope` は所有戦闘の同期更新中だけ有効。`Context::write` でword19への正の増分を読み取り、`InspectorSourceScope` で命中関数の攻撃元を結び付ける。actor_hitは直接・波動・烈波・爆波・毒撃などの共通入口、砲step/hitとスニャイパーhitは専用の原因種別にする。原本00a9bbacの加算・城無敵の分岐や命中条件を変えず、予約されなかった攻撃・0ダメージは追加しない。word19が0へ戻されたら、その対象の未確定原因も消す。

予約原因とメタルキラーの補助配列は枠ごとのvectorを再利用し、各Fで確保・解放を繰り返さない。既知の命中入口では32bit差分で加算量を観測し、符号付き予約値の桁あふれも式自体を変えず追跡する。

`BattleInspector::begin` は各論理Fの予約原因をクリアし、health/reactで正のHP→0、かつ保護処理後に正の予約が残った場合だけ当該Fの原因を保存する。残るのは「同じFにHPへ反映された攻撃元」であり、唯一の撃破者を断定しない。予約量は盾などの処理前なので、表示する場合も「予約量」と呼び、各キャラの実与ダメージへ読み替えない。蘇生動作の開始で過去の撃破元表示を解除する。

遅延適用するメタルキラーは予約と同時に攻撃元を別途保存し、率配列と同順で再適用時の原因へ戻す。烈波・反射待ち・爆波の非公開所有レコードにも生成時の攻撃元id/profileを保存し、元の個体枠の再利用後に別個体の画像へ化けることを防ぐ。公開の攻撃PODや数値処理は変更しない。波動は既存の退場待ちで所有枠を保持している。解決できない攻撃元は「その他」とし、対象キャラの画像で埋めない。

`kbcs_core_battle_inspection_sources(id)` → bridge借用 → Sessionのページ応答のattackersへ添付する。左右2件までの任意要求を同じ戦闘フレームRPCで受け、表示しない側は送らない。選択した個体の詳細は各一覧内の折りたたみへ置き、開いている時だけ更新する。

回帰検査: 2体の攻撃が同じFにメタル敵を撃破するケースで両方の生成idとprofileを確認。バリアに吸収された過去Fの攻撃元が後の撃破へ混入しないこと、単独攻撃元への切替、「すべて」の区分順も検査する。実画面の確認は利用者が担当する。
