# ネイティブ関数のバージョン間追跡 v2

同じABI・ライブラリの3版を取り、隣接2区間を比較する。最初と最後の直接比較は経路の検証に使う。2版でも動作し、4版以上の結果は重なる複数ウィンドウから照会できる。関数のキーは版、ABI、SO SHA-256、解析リビジョン、入口アドレスの組。関係は根拠付きで保存する。

## 実行と検索

解析・資料が公開済みの版は、Actionsで完成checkpointを指定して `stage=match` を実行する。[初回の指定値と再実行手順](../../docs/actions-analysis.md)

ローカルでは各版の完成済みキャッシュ、SHA-256を照合したSO、構造エクスポートを指定する。バックフィルは隔離プロジェクトを使用する。古い索引の関数境界を照合し、再解析で境界が変わった箇所を区別する。
構造索引と追跡DBの作業領域を別ドライブに置く場合は `build --output <ディレクトリ>` を指定する。

```powershell
$env:PYTHONPATH = (Resolve-Path research).Path
python -m matcher.tracking backfill --cache <キャッシュ> --binary <検証済みSO> --config research/.local/config.json
python -m matcher.tracking build --dataset <cache-A> <SO-A> <structure-A.gz> --dataset <cache-B> <SO-B> <structure-B.gz> --dataset <cache-C> <SO-C> <structure-C.gz>
python -m matcher.tracking show 15.7.4 <アドレス> --db <tracking.sqlite> --limit 5
python -m matcher.tracking trace 15.7.2 <アドレス> --db <tracking.sqlite> --db <次のウィンドウのSQLite>
```

`show` は関係の根拠、比較範囲、P-codeの変更抜粋、参照位置を返す。`trace` は隣接関係をたどり、矛盾する関係と途中版に経路が見つからない再登場候補を別に返す。任意の既存照合DBを再利用する場合は `build --pair-db 0-1 <matches.sqlite>` のように指定する。両側の索引SHA、版・ABI・SO SHAと名前付きホールドアウトの検証結果を照合する。

手動判断は `research/comparisons/decisions/<旧版>--<新版>.json` に、[2版照合の形式](README.md#検証と人の修正)で保存する。ローカルの `build --decisions <ディレクトリ>` でも使える。索引SHAの異なる判断は流用しない。採用した手動判断と他経路が食い違えば、経路矛盾として残る。

## データと処理

| 工程 | 関数と証拠 |
|---|---|
| 1 | `report.build` が既存の名前、指紋、アドレス順、参照・呼出を使う。採用、候補、保留を取り込み、全関数を `nodes` に登録する。 |
| 2 | `ExportStructure` が実際の本体範囲とCFG、呼出・データ参照、命令別raw P-codeを抽出する。`structure.build_index` が版の索引と比較し、境界差や未解決間接フローを記録する。`tracking_pair.refine` は両版で一意なCFG・P-code指紋、厳密なP-code比較、初期対応済みの複数の呼出関係が揃った組だけを追加採用する。 |
| 3 | `logic.compare` が変更・未対応の呼出近傍と、構造指紋や命令バイトの違う関数を比較する。条件分岐、演算・定数、呼出、読み書き、ブロック内の定義と利用、命令順序の差を旧新版の位置付きで保存する。 |
| 4 | `tracking_pair.intervals/residuals` が基準間の個数差・交差、競合候補、P-code断片の包含を調べる。分割・統合・インライン化の候補は1対1の採用と別に保存する。関数数が等しい区間でも両端を根拠に追加・削除候補を記録できる。 |
| 5 | `tracking.reconcile` が連続・直接経路の一致、矛盾、部分経路、再登場、一時変化の候補を記録する。`tracking_pages.render/attach` は検証済み結果から資料を生成し、版の目次にリンクする。 |

`tracking.sqlite` の `datasets` と `node_structure` が解析出典・本体・CFGを保持する。`xrefs` は呼出位置、宛先、READ/WRITE、Ghidraが特定したデータ型・シンボルを保持する。間接呼出は宛先を解決できた範囲を記録する。VTableやジャンプテーブルの候補はGhidraに参照・データ型・シンボルがある範囲で追跡できる。`pairs`、`relations`、`candidates`、`logic`、`review`、`layout`、`cycles`、`manual_decisions` に比較・検査結果を分離する。入力・エンジン・手動判断が同じ完成DBは整合性を確認して再利用する。

## 読み方と検査範囲

- `logic_change_candidate` は正規化後にもP-codeの差が残った組。公開資料は分岐・演算順序・呼出などの変化を含む優先確認と、定数・オペランド中心の候補を分ける。コンパイラの最適化による違いを含み得る。
- `register_sensitive` と `reference_sensitive` はレジスタ割当や参照アドレスに依存する差。ARM64のADR・ADRPと、計算値が解析索引の参照先に一致する直後のオフセットは分類に使う。厳密比較のオペランド、演算定数、ビットマスクは保持する。
- `machine_cfg_equal` は命令バイトのハッシュ、CFGと構造指紋の一致。詳細検査の `no_difference_in_scope` と検査範囲を区別する。`machine_only_observed` は機械語の差を観測し、選択したP-code・CFG・参照の比較では差を確認できなかった組。
- P-codeは命令からのraw P-codeを用いる。ブロック間のSSA、別名解析、動的に選ばれる呼出先やデータの意味は別途検証する。復元できない境界や間接フローは保留する。
- スコアは候補の順位付け用。経路の一致は共通の解析器に依存する。追加・削除・分割・統合・再登場は候補として表示する。

公開資料は `research/comparisons/<ABI>/<実行ID>/` に分離する。版の目次とページを経由して、旧新版の関数、呼出元・先、変更箇所へ移動できる。参照先は公開時のGitコミットへ固定する。SQLiteは解析Releaseで配布する。旧15.7.2→15.7.4の公開ページ・差分・専用リンクは、新方式の検査済み結果と同一コミットで入れ替える。元の疑似コード、SOの検証情報、完成checkpointと解析Releaseを保全する。

## 検証

`python -m unittest matcher.test_tracking` で同数区間の追加・削除、並び替え、同型関数、分割・統合・インライン化、経路矛盾、一時変化、4版への拡張、中断後の再構築、原本保護、公開リンクを検査する。独立したARM64 ELFの実抽出は `KBCS_TEST_GHIDRA=1`、`GHIDRA_HOME`、`JAVA_HOME` を設定して実行する。名前を隠した検証の正答・誤対応・保留は各組の集計に保存する。

### 15.7.2・15.7.3・15.7.4の実測

検証済みのARM64 SOと3版の完成済みチェックポイントから、全76,571件の関数レコードを取り込んだ。名前付きホールドアウトは各経路1,477件。

| 経路 | v1の内部対応 | 構造による追加採用 | ホールドアウト正答 / 誤対応 / 保留 |
|---|---:|---:|---:|
| 15.7.2 → 15.7.3 | 23,345 | 5 | 1,350 / 0 / 127 |
| 15.7.3 → 15.7.4 | 23,508 | 4 | 1,345 / 0 / 132 |
| 15.7.2 → 15.7.4（検証） | 23,120 | 1 | 1,350 / 0 / 127 |

3経路の一致は23,372件（外部292件を含む）。矛盾0件、部分経路274件、再登場候補36件。一致のうち93件で一時変化候補を記録した。15.7.2→15.7.3のP-code変更候補は優先確認1,376件、定数・オペランド中心9,210件。15.7.3→15.7.4ではそれぞれ614件、9,814件。Ghidra再解析結果と保存済み索引の境界・命令範囲が揃わなかった件数は順に82、1、1件。間接フローの未解決も台帳で区別した。

Windowsでの構造出力は各版約36MiB、抽出部分は103〜158秒。15.7.3と15.7.4は自動解析から約27分、約26分。3経路の初期照合DBを用いた追跡は24分10秒、Pythonの最大ワーキングセット約726MiB、追跡SQLite約485MiB。公開形式のMarkdownは562ページで、リンク先を含め約100秒で生成・検査した。

独立ELFで確認した変更は閾値、分岐条件、呼出、書込の4種類。実データの全関数について挙動の正解データはなく、匿名関数の正答率とロジック変化の網羅率は未測定。
