# ネイティブ関数のバージョン間追跡 v2

同じABI・ライブラリの3版を取り、隣接2区間を比較する。最初と最後の直接比較は経路の検証に使う。2版でも動作し、4版以上の結果は重なる複数ウィンドウから照会できる。関数のキーは版、ABI、SO SHA-256、解析リビジョン、入口アドレスの組。関係は根拠付きで保存する。

## 実行と検索

解析・資料が公開済みの版は、Actionsで完成checkpointを指定して `stage=match` を実行する。初回は `stage=backfill` で不足する構造を保全してから照合できる。[初回の指定値と再実行手順](../../docs/actions-analysis.md)

ローカルでは各版の完成済みキャッシュ、SHA-256を照合したSO、構造エクスポートを指定する。バックフィルは隔離プロジェクトを使用する。古い索引の関数境界を照合し、再解析で境界が変わった箇所を区別する。
構造索引と追跡DBの作業領域を別ドライブに置く場合は `build --output <ディレクトリ>` を指定する。

```powershell
$env:PYTHONPATH = (Resolve-Path research).Path
python -m matcher.tracking backfill --cache <キャッシュ> --binary <検証済みSO> --config research/.local/config.json
python -m matcher.tracking build --dataset <cache-A> <SO-A> <structure-A.gz> --dataset <cache-B> <SO-B> <structure-B.gz> --dataset <cache-C> <SO-C> <structure-C.gz>
python -m matcher.tracking show 15.7.4 <アドレス> --db <tracking.sqlite> --limit 5
python -m matcher.tracking trace 15.7.2 <アドレス> --db <tracking.sqlite> --db <次のウィンドウのSQLite>
```

`show` は関係の根拠、比較範囲、P-codeの変更抜粋、参照位置を返す。`trace` は隣接関係をたどり、矛盾する関係と途中版に経路が見つからない再登場候補を別に返す。任意の既存照合DBを再利用する場合は `build --pair-db 0-1 <matches.sqlite>` のように指定する。両側の索引SHA、版・ABI・SO SHAと名前付きホールドアウトの検証結果を照合する。

手動判断は `research/comparisons/decisions/<旧版>--<新版>.json` に、[2版照合の形式](README.md#検証と人の修正)で保存する。ローカルの `build --decisions <ディレクトリ>` でも使える。索引SHAの異なる判断は流用しない。採用した手動判断と他経路が食い違えば、経路矛盾として残る。

要調査の候補はSQLiteでも絞り込める。

```sql
SELECT pair, old, new, status, json_extract(evidence, '$.confidence') AS confidence
FROM logic
WHERE pair = '0-1' AND json_extract(evidence, '$.importance') = 'review'
LIMIT 20;
```

## データと処理

| 工程 | 関数と証拠 |
|---|---|
| 1 | `report.build` が既存の名前、指紋、アドレス順、参照・呼出を使う。採用、候補、保留を取り込み、全関数を `nodes` に登録する。 |
| 2 | `ExportStructure` が本体範囲、CFG、参照、命令別raw P-codeを抽出する。`structure.build_index` が境界差や未解決間接フローを記録する。`tracking_pair.refine` は両版で一意な構造、厳密なP-code一致、2組以上の対応済み呼出関係を求める。少なくとも1組は初期matcher由来とし、最大5ラウンドで新規採用の呼出近傍だけを再評価する。 |
| 3 | `logic.reference_comparison` は機械語・CFGとは独立に、呼出先の対応、データ参照先、アクセス方向、入口相対の命令位置を比較する。`logic.compare` と `effects.changes` はSTOREの宛先・値・ガード、分岐値、呼出先・引数候補、戻り値候補を定義位置と合わせて記録する。 |
| 4 | `tracking_pair.intervals/residuals` は基準間の個数・順序・競合・P-code断片を調べる。分割、統合、インライン化、対応済み関数への埋め込み、追加・削除の仮説を併記する。旧版と新版の関数数が同じ場合も、区間に強い対応が見つからなければ追加・削除候補を検討する。 |
| 5 | `tracking.reconcile` が連続・直接経路の一致、矛盾、部分経路、再登場、一時変化の候補を記録する。`tracking_pages.render/attach` は検証済み結果から資料を生成し、版の目次にリンクする。 |

`tracking.sqlite` の `datasets` と `node_structure` が解析出典・本体・CFGを保持する。`xrefs` は呼出位置、宛先、READ/WRITE、Ghidraが特定したデータ型・シンボルを保持する。間接呼出は宛先を解決できた範囲を記録する。VTableやジャンプテーブルの候補はGhidraに参照・データ型・シンボルがある範囲で追跡できる。`pairs`、`relations`、`candidates`、`logic`、`review`、`layout`、`cycles`、`manual_decisions` に比較・検査結果を分離する。入力・エンジン・手動判断が同じ完成DBは整合性を確認して再利用する。

## 読み方と検査範囲

- 重要度（`critical`、`high`、`review`、`none`）と確度（`observed`、`bounded`、`limited`）は別に保存する。STOREの個数が同じでも宛先や値の差を追跡する。最優先の判定では、PC相対アドレスの役割や対応済み関数へのポインタを揃えて影響を再評価する。生の証拠は `effects`、再配置に依存する件数は `address_sensitive_impact`、その検査後に残る影響は `priority_impact` に保存する。参照差だけでも高優先で調査できる。
- `register_renaming_candidate` は、確認した範囲で定義・使用と影響先が揃う割当差。入力や部分レジスタの定義が追えない場合は `register_sensitive` に残す。ADR・ADRPなどの分類にも厳密なオペランドを保存する。
- `detail_skipped` は命令ハッシュ、CFG、構造指紋、記録済み参照が一致した組。未検査項目を保存する。参照に差または未解決があれば詳細検査へ進む。`no_difference_in_scope`、`machine_only_observed`、`reference_unresolved`、`unavailable` は検査範囲が異なる。
- 値追跡はraw P-codeの基本ブロック内を対象にする。書込条件は、合流を挟まない唯一の前任経路から確認できる範囲に限る。AArch64の引数候補は整数レジスタx0〜x7、戻り値候補はx0に基づく。関数の型、スタック・ベクトル引数、ブロック間SSA、動的な別名・間接参照は未検査として記録する。High P-codeは使用しない。
- スコアは候補の順位付け用。経路の一致は共通の解析器に依存する。追加・削除・分割・統合・再登場は候補として表示する。

公開資料は `research/comparisons/<ABI>/<実行ID>/` に分離する。版の目次とページを経由して、旧新版の関数、呼出元・先、変更箇所へ移動できる。参照先は公開時のGitコミットへ固定する。SQLiteは解析Releaseで配布する。旧15.7.2→15.7.4の公開ページ・差分・専用リンクは、新方式の検査済み結果と同一コミットで入れ替える。元の疑似コード、SOの検証情報、完成checkpointと解析Releaseを保全する。

## 検証

`python -m unittest matcher.test_tracking` で同数区間の追加・削除、並び替え、同型関数、分割・統合・インライン化、経路矛盾、一時変化、4版への拡張、中断後の再構築、原本保護、公開リンクを検査する。独立したARM64 ELFの実抽出は `KBCS_TEST_GHIDRA=1`、`GHIDRA_HOME`、`JAVA_HOME` を設定して実行する。名前を隠した検証の正答・誤対応・保留は各組の集計に保存する。

### 改善前の15.7.2・15.7.3・15.7.4実測

検証済みのARM64 SOと3版の完成済みチェックポイントから、全76,571件の関数レコードを取り込んだ。名前付きホールドアウトは各経路1,477件。

| 経路 | v1の内部対応 | 構造による追加採用 | ホールドアウト正答 / 誤対応 / 保留 |
|---|---:|---:|---:|
| 15.7.2 → 15.7.3 | 23,345 | 5 | 1,350 / 0 / 127 |
| 15.7.3 → 15.7.4 | 23,508 | 4 | 1,345 / 0 / 132 |
| 15.7.2 → 15.7.4（検証） | 23,120 | 1 | 1,350 / 0 / 127 |

3経路の一致は23,372件（外部292件を含む）。矛盾0件、部分経路274件、再登場候補36件。一致のうち93件で一時変化候補を記録した。15.7.2→15.7.3のP-code変更候補は優先確認1,376件、定数・オペランド中心9,210件。15.7.3→15.7.4ではそれぞれ614件、9,814件。Ghidra再解析結果と保存済み索引の境界・命令範囲が揃わなかった件数は順に82、1、1件。間接フローの未解決も台帳で区別した。

Windowsでの構造出力は各版約36MiB、抽出部分は103〜158秒。15.7.3と15.7.4は自動解析から約27分、約26分。3経路の初期照合DBを用いた追跡は24分10秒、Pythonの最大ワーキングセット約726MiB、追跡SQLite約485MiB。公開形式のMarkdownは562ページで、リンク先を含め約100秒で生成・検査した。

独立ELFで確認した変更は閾値、分岐条件、呼出、書込の4種類。実データの全関数について挙動の正解データはなく、匿名関数の正答率とロジック変化の網羅率は未測定。

### 参照検査と値追跡を改善した実測

同じ3版の原本・構造・初期照合DBを使用した。内部関数の採用は順に23,350、23,512、23,121組で、改善前と同数。3経路の一致23,372件、矛盾0件、部分経路274件、再登場候補36件。未解決参照を区別した結果、一時変化候補は93件から56件になった。実データでは2ラウンド目以降の追加採用はなく、後続ラウンドでの採用と推測の連鎖防止は独立したテストで確認した。

| 経路 | 旧優先一覧 | 新最優先候補 | 詳細検査 / 省略 / 解析不能 | 参照が理由で詳細検査へ移行 |
|---|---:|---:|---:|---:|
| 15.7.2 → 15.7.3 | 1,376 | 8,586 | 20,485 / 2,501 / 656 | 154 |
| 15.7.3 → 15.7.4 | 614 | 8,327 | 20,785 / 2,445 / 574 | 151 |
| 15.7.2 → 15.7.4（検証） | 1,904 | 8,756 | 20,973 / 1,785 / 655 | 114 |

実データで詳細検査へ移行した419組には未解決参照が残っていた。機械語・CFGが一致して参照先だけが変わる例は回帰テストで確認した。既知のアドレス生成を考慮した再判定で、各経路412、538、466組を最優先から外した。未対応・競合と追加・削除の仮説は重複し得るため、候補件数は確定関数数と別に読む。

| 経路 | 書込の影響候補 | 分岐値・分岐数の影響候補 | 呼出引数の影響候補 | 最優先のうち確度limited |
|---|---:|---:|---:|---:|
| 15.7.2 → 15.7.3 | 6,218 | 1,093 | 3,873 | 5,992 |
| 15.7.3 → 15.7.4 | 5,955 | 775 | 3,563 | 5,684 |
| 15.7.2 → 15.7.4（検証） | 6,076 | 1,354 | 3,714 | 6,164 |

15.7.3の `00b00094` と15.7.4の `00b000d8` では、書込値に残るアドレス差を保持し、アドレス生成の検査後に高優先へ移した。15.7.2の `00afacd8` と15.7.3の `00afada0` では、0と比較する分岐に渡る定義が異なる候補を記録した。新版側の定義を基本ブロック内で解決できなかったため、挙動の判定は保留した。候補件数は真の機能変更数とは区別する。

Windowsでは既存初期照合を使った追跡とSQLite作成に36分25秒、優先判定の再評価に13分34秒。Pythonの最大ワーキングセットは約499MiB、完成SQLiteは約580MiB。各PASSの秒数、累積最大RSS、重要度、未解決参照、候補種別はSQLiteと集計JSONに保存した。最終プレビューは617ページ、408,423リンクで、生成と検査に56秒。旧資料の移行は独立worktreeで、リンクを確認した後に、旧比較369ファイルと関連文書2ファイルを除去し、関数資料46,824件から旧ナビゲーションだけを外した。GitHubでのバックフィルと公開は別に実行する。
