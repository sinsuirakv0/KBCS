## クエスト・迷宮・章・EX

クエストの戦闘用0099fe4cはgame+389910のpacked参照を100で割ったRNマップ/面を使う。迷宮は0071b5b4が返すテンプレート番号を使い、実際の階数をファイル番号へ直結しない。テンプレートは100以上も実在する。Rust resolverは必要な参照値がないと拒否する。参照値の抽選/生成自体はこの選択器の検証外。

章の通常ファイルは設定行が1行、ゾンビ/襲来と通常系列は設定行が2行。通常日本編は章にかかわらずstageNN、未来編はstageW04..06、宇宙編はstageSpace07..09。ゾンビはmode番号のstageZ、襲来はstageSpaceNN_Invasion_00、ゾンビ襲来はInvasion_Z_00。実ステージが指定されても襲来のファイル面は0固定。EX戦闘mode99では現在面番号ではなく専用EX index/stageを使う。一覧用EXは別の入力。

## 再出現区間の逆転

RA068-1の物理6行は再出現600..300F、RSR021-2の物理6行は2200..2100F。原本006ef2b0は(max−min)+1をそのまま0044a8d8へ渡し、0044a8e8が非正boundなら0を返して状態を進めない。その結果minを待機値へ保存する。個体生成のレイヤー範囲のクランプとは別。

C++の入力検査を修正し、この2行を受理する。Random::boundedは非正boundで0/状態不変、bound1では状態更新。実RNGを含む両出現処理も再実行し、全体待機だけが乱数を1回消費することを確認した。非0明示シードは引き続き必須。状態0のOS初期化は移植しない。正のboundでi32の加算範囲を超える入力は製品側で拒否する。

## XPの取得元

0058bad0のmode3ではkind0/−9/−22がCSV元値×9、min(clears,4)/5を減算する。他のkindではCSV元値をそのまま使い減衰しない。mode99のEXも元値のまま。章はCSV元値を無視し(stage×6000+20000)/10を作り、min(clears,13)/14を減算する。その後は勉強力・お宝→コンボ→おかめの整数化を既存実装と共用する。

band_experience.pyは減衰helperの呼出/非呼出も検査した。kind全域と章/EXの境界304条件、一覧の通常報酬表から10788条件。EXのMapStageDataREは通常の報酬行として読まないため、実表のXP元値の解決は別途必要。章の保存先選択・実所持数付与・アカウント保存は含めない。

## ファイルと関数の関係

stage_sources.py → stage-source-vectors.json → stage_source::{decode,encode,current_kind,resolve}。IDと現在種別の算術はmap.cpp、文字列/参照値解決はRust。stage_bands.py → band-row-vectors.json → stage::Row::decode → kbcs_core_stage_row_decode → 既存tick/commit。band_experience.py → band-experience-vectors.json → experience::stage → kbcs_core_stage_experience → 既存の共通補正。既存legend/eventのABI入力は変更しない。

原本encodeはindex範囲外でも別番台へ流出できるが、製品APIは各bandの範囲を検査する。負ID、40000以上を拒否。decodeのkind−1は未分類を表し、有効なファイルが存在する証明ではない。
